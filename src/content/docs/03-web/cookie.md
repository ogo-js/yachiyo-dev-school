## このページでできるようになること

- サーバーが Cookie を渡し、ブラウザがそれを送り返す流れを、開発者ツールで確かめられる
- 「サーバーが状態を持たない」作りを説明できる
- Cookie の中身を書き換えられてしまう危うさと、その防ぎ方の考え方を説明できる

かかる時間の目安は40分です。

## 始める前に

レッスン3-3（JSON と API）を終え、`~/practice/web/webdemo.py` ができている必要があります。

## なぜこれを覚えるのか

HTTP のやり取りは1回ごとに切れています。サーバーは、さっきのリクエストと今のリクエストが同じ人からのものかを、そのままでは見分けられません。

それでも、一度ログインすれば次のページでもログインしたままになります。この「ログインしている」という状態は、どこに保たれているのでしょうか。それを確かめるのが、このレッスンです。

## ログインしていない状態を見る

練習用のサーバーを動かします。

```bash
cd ~/practice/web
python3 webdemo.py
```

ブラウザで `http://localhost:8000/me` を開きます。

```text
ログインしていません
yachiyo としてログイン
```

開発者ツールのネットワークのタブを開いておきます。

## ログインする

「yachiyo としてログイン」のリンクを押します。「yachiyoさんとしてログインしました」と表示されます。

ネットワークのタブで `login?user=yachiyo` の行を押し、「ヘッダー」のタブで「応答ヘッダー」（Response Headers）を見ると、次の行があります。

```text
Set-Cookie: user=yachiyo; Path=/
```

`Set-Cookie` は、サーバーからブラウザへの「この値を覚えておいて、次から毎回見せて」というお願いです。ブラウザが覚えておく小さな値を「Cookie」と呼びます。

## Cookie が送り返される

「確かめる」のリンクを押すと、`/me` が「ログイン中：yachiyoさん」に変わります。

ネットワークのタブで `me` の行を押し、今度は「要求ヘッダー」（Request Headers）を見ると、次の行があります。

```text
Cookie: user=yachiyo
```

ブラウザが覚えていた Cookie をリクエストに付けて送っています。サーバーはこの値を見て、誰からのリクエストかを判断しています。

ブラウザが覚えている Cookie は、開発者ツールの「アプリケーション」（Application）のタブで見られます。左のメニューの「Cookie」から `http://localhost:8000` を選ぶと、`user` という名前で `yachiyo` という値が並んでいます。

## サーバーを再起動しても、ログインしたまま

サーバーのターミナルで Ctrl+C を押して止め、もう一度動かします。

```bash
python3 webdemo.py
```

ブラウザで `/me` を読み込み直してください。「ログイン中：yachiyoさん」のままです。

サーバーは、誰がログインしているかを何も覚えていません。止めて動かし直せば、なおさらです。それでもログインしたままなのは、ログインの状態を表す値をブラウザが持っていて、リクエストのたびに送ってくるからです。

このように、サーバーが利用者ごとの状態を覚えておかず、必要な情報をリクエストのたびに受け取る作りを「ステートレス（状態を持たない）」と呼びます。

## サーバーが状態を覚える作りとの違い

ステートレスでない作りもあります。サーバーが「この番号の人は yachiyo さん」という表を自分のメモリに持ち、ブラウザには番号だけを渡す作りです。

| | サーバーが覚える作り | ステートレスな作り |
| --- | --- | --- |
| ログインの情報があるところ | サーバーのメモリ | ブラウザ（毎回送られてくる） |
| サーバーを再起動すると | 表が消えて、全員がログアウトする | ログインしたまま |
| サーバーを2台に増やすと | もう1台は表を持っていないので、うまく動かない | どちらのサーバーでも同じように判断できる |

利用者が増えたときにサーバーの台数を増やしやすいので、今の Web アプリではステートレスな作りがよく使われます。

## Cookie は書き換えられる

アプリケーションのタブで、`user` の値の `yachiyo` をダブルクリックし、`tanaka` に書き換えてみてください。`/me` を読み込み直すと、次のように表示されます。

```text
ログイン中：tanakaさん
```

ログインしていない人に、なりすませてしまいました。Cookie はブラウザの中にあるので、利用者が自由に書き換えられます。この練習用のサーバーは送られてきた名前をそのまま信じているので、だまされてしまいます。

:::caution
本物のアプリでは、Cookie にただの名前を入れることはしません。サーバーだけが知っている鍵を使って中身に「署名」を付け、書き換えられていたら見破れるようにします。この仕組みの代表的なものが JWT（JSON Web Token）です。仕組みの詳しい中身はこの教材では扱いません。
:::

## ログアウトする

`/me` の「ログアウト」のリンクを押します。応答ヘッダーには、次の行があります。

```text
Set-Cookie: user=; Path=/; Max-Age=0
```

「`user` の値を空にして、すぐに捨てて」というお願いです。アプリケーションのタブを見ると、`user` の Cookie が消えています。

## 困ったとき

- **アプリケーションのタブに Cookie が出てこない**：左のメニューの「Cookie」の左にある三角を押して開き、`http://localhost:8000` を選んでください。
- **書き換えた Cookie が元に戻ってしまう**：値を書き換えた後に Enter キーを押して確定させてください。

## 確かめよう

1. ブラウザのアドレス欄に `http://localhost:8000/login?user=suzuki` と打って開き、応答ヘッダーの `Set-Cookie` を確かめる
2. `/me` を開き、要求ヘッダーの `Cookie` を確かめる
3. サーバーを再起動して、`/me` がログインしたままであることを確かめる
4. ログアウトして、アプリケーションのタブから Cookie が消えたことを確かめる

1で `Set-Cookie: user=suzuki; Path=/`、2で `Cookie: user=suzuki`、3で「ログイン中：suzukiさん」、4で Cookie の一覧が空になっていれば完了です。確かめたら、Ctrl+C でサーバーを止めます。

## 今は知らなくてよいこと

- 署名の仕組みと JWT の中身
- Cookie の細かい設定（有効期限、HttpOnly、Secure など）
