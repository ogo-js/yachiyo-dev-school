## このページでできるようになること

- 手元のパソコンで、小さな Web サーバーを動かせる
- ブラウザの開発者ツールで、リクエストとレスポンスを見られる
- ステータスコード（200 や 404）の意味が分かる

かかる時間の目安は40分です。

## 始める前に

第1部（コマンドライン）を終えている必要があります。

## なぜこれを覚えるのか

Web のアプリはブラウザとサーバーの間で「お願い」と「返事」をやり取りして動いています。ブラウザからのお願いを「リクエスト」、サーバーからの返事を「レスポンス」と呼びます。

画面が思ったとおりに動かないとき、原因がブラウザ側にあるのかサーバー側にあるのかを切り分けるには、このやり取りを見るのが一番の近道です。このレッスンでは両方の側からやり取りを見ていきます。

## ページを用意する

練習用のフォルダを作り、HTML のファイルを1つ置きます。

```bash
mkdir -p ~/practice/web
cd ~/practice/web
touch index.html
code index.html
```

`mkdir -p` は「途中のフォルダがなければ一緒に作る。すでにあってもエラーにしない」という意味です。

VS Code で開いた `index.html` に、次の4行を書いて保存します。

```html
<!doctype html>
<html lang="ja"><meta charset="utf-8"><title>はじめてのページ</title>
<h1>こんにちは</h1>
</html>
```

## サーバーを動かす

Ubuntu には、プログラミング言語の Python が最初から入っています。Python にはフォルダの中のファイルをそのまま返す、小さなサーバーが付いています。

```bash
python3 -m http.server 8000
```

```text
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
```

この表示のまま、ターミナルが止まったように見えます。サーバーが動いていて、リクエストを待っている状態です。止めるときは Ctrl キーを押しながら C キーを押します。

`8000` は「ポート番号」です。1台のパソコンの中で、どのサーバーにつなぐかを見分けるための番号です。

## ブラウザで開く

Windows のブラウザ（Edge や Chrome）で、次の URL を開きます。

```text
http://localhost:8000
```

「こんにちは」と大きく表示されれば成功です。`localhost` は「このパソコン自身」を指す名前です。WSL2 の中で動かしたサーバーに、Windows のブラウザからつながっています。

## サーバーの側から見る

ターミナルを見ると、行が増えています。

```text
127.0.0.1 - - [20/Oct/2026 15:00:00] "GET / HTTP/1.1" 200 -
127.0.0.1 - - [20/Oct/2026 15:00:00] code 404, message File not found
127.0.0.1 - - [20/Oct/2026 15:00:00] "GET /favicon.ico HTTP/1.1" 404 -
```

1行が1回のリクエストの記録です。この記録を「ログ」と呼びます。日時は実際に開いた時刻になります。

- `GET /`：「`/`（一番上のページ）をください」というリクエスト
- `200`：「はい、どうぞ」という返事。うまくいったことを表します
- `GET /favicon.ico` と `404`：ブラウザがタブに出す小さな絵（favicon）を自動でお願いしたが、「そんなファイルはない」と返された

## ブラウザの側から見る：開発者ツール

ブラウザで F12 キーを押すと、「開発者ツール」が開きます。開発者がページの裏側を調べるための道具です。

1. 開発者ツールの上に並んだタブから、「ネットワーク」（Network）を選びます。
2. その状態で F5 キーを押して、ページを読み込み直します。

一覧に、リクエストが1行ずつ並びます。`localhost` の行を押すと、そのリクエストの詳細が出ます。

「ヘッダー」（Headers）のタブでは、次のことが分かります。

| 項目 | 表示の例 | 意味 |
| --- | --- | --- |
| 要求 URL（Request URL） | `http://localhost:8000/` | どこにお願いしたか |
| 要求メソッド（Request Method） | `GET` | どんな種類のお願いか |
| 状態コード（Status Code） | `200 OK` | 返事の結果 |

「応答」（Response）のタブには、サーバーが返した中身が表示されます。`index.html` に書いた4行がそのまま返ってきています。ブラウザはこの中身を読んで画面を描いています。

:::note
開発者ツールの言葉はブラウザの種類や言語の設定で少し違います。英語の場合は、括弧の中の名前を見てください。
:::

## ないページを開く

ブラウザで、次の URL を開いてみます。

```text
http://localhost:8000/nothing.html
```

「Error response」「File not found」のような画面が出ます。開発者ツールのネットワークのタブを見ると、状態コードが `404` になっています。ターミナルのログにも `404` の行が増えています。

## ステータスコード

レスポンスには、結果を表す3桁の番号が必ず付きます。これを「ステータスコード」と呼びます。最初の1桁で、大まかな意味が分かります。

| 番号 | 意味 | よく見る例 |
| --- | --- | --- |
| 2で始まる | うまくいった | `200 OK` |
| 3で始まる | 別の場所へ行ってほしい | `302 Found` |
| 4で始まる | お願いの側に問題がある | `404 Not Found`（ない）、`400 Bad Request`（お願いの形がおかしい） |
| 5で始まる | サーバーの側で問題が起きた | `500 Internal Server Error` |

画面がおかしいときは、まず開発者ツールでステータスコードを見ると、どちらの側を調べればよいかの見当がつきます。

## 困ったとき

- **「Address already in use」と出た**：8000番のポートを、別のサーバーがすでに使っています。前に動かしたサーバーが残っていないか確かめ、残っていたら Ctrl+C で止めてください。
- **ブラウザで「接続が拒否されました」と出た**：サーバーが動いていません。ターミナルで `python3 -m http.server 8000` が動いているか確かめてください。
- **ページを直したのに表示が変わらない**：ブラウザが古い中身を覚えています。Ctrl キーを押しながら F5 キーを押すと、覚えている中身を使わずに読み込み直します。

## 確かめよう

1. `~/practice/web` に `about.html` を作り、`<h1>このサイトについて</h1>` と書いて保存する
2. サーバーを動かし、ブラウザで `http://localhost:8000/about.html` を開く
3. 開発者ツールで、`about.html` のリクエストのメソッドとステータスコードを確かめる
4. ブラウザで `http://localhost:8000/about` （`.html` なし）を開き、ステータスコードを確かめる

3で `GET` と `200`、4で `404` が確かめられれば完了です。ターミナルのログにも、同じ番号の行が出ていることを確かめてください。確かめたら、Ctrl+C でサーバーを止めます。
