## このページでできるようになること

- 手で確かめる場合と、自動テストの違いを説明できる
- Vitest で、関数のテストを書いて動かせる
- テストが失敗したときの表示を読める

かかる時間の目安は40分です。

## 始める前に

第6部（TypeScript）を終えている必要があります。このレッスンでは `~/practice/js1` を使います。

## 手で確かめることの限界

ここまでのレッスンでは動かして、目で結果を見て確かめてきました。小さなプログラムなら、それで足ります。

アプリが大きくなると、こうはいきません。税の計算を1か所直したら、その計算を使っている画面をすべて開いて確かめ直す必要があります。100の画面があれば100回です。確かめ忘れた所で、知らないうちに壊れていた、ということが起きます。

自動テストは「この関数にこれを渡したら、これが返るはず」という確かめを、プログラムとして書いておくものです。書いておけば、何度でも、一瞬で、同じように確かめ直せます。

| | 手で確かめる | 自動テスト |
| --- | --- | --- |
| かかる時間 | 確かめるたびに、人の手間がかかる | 書くのに手間がかかるが、動かすのは一瞬 |
| 確かめ忘れ | 起きる | 書いたものは、毎回すべて確かめる |
| 直した後の確かめ直し | 大変なので、つい省く | コマンド1つでできる |
| 何を確かめたかの記録 | 残りにくい | テストのコードとして残る |

## Vitest を入れる

TypeScript のテストには Vitest（ヴィテスト）という道具を使います。

```bash
cd ~/practice/js1
npm install --save-dev vitest
```

## テストする関数を書く

`price.ts` を作り、税込みの値段を返す関数を書いて保存します。1円未満は切り捨てます。

```typescript
export function withTax(price: number): number {
  return Math.floor(price * 1.1);
}
```

`export` を付けているのは、テストのファイルから使えるようにするためです。`Math.floor` は、小数点以下を切り捨てます。

## テストを書く

テストのファイルはテストする相手の名前に `.test` を付けた名前にします。`price.test.ts` を作って、次の内容を書いて保存します。

```typescript
import { describe, expect, test } from "vitest";
import { withTax } from "./price";

describe("withTax", () => {
  test("1000円の税込みは1100円", () => {
    expect(withTax(1000)).toBe(1100);
  });

  test("1円未満は切り捨てる", () => {
    expect(withTax(105)).toBe(115);
  });

  test("0円は0円", () => {
    expect(withTax(0)).toBe(0);
  });
});
```

- `test("…", () => { … })`：テストを1つ書く。最初の文字列は何を確かめるテストかの説明
- `expect(実際の値).toBe(期待する値)`：「実際の値が、期待する値と同じであること」を確かめる
- `describe("…", () => { … })`：関係するテストをまとめる

105円の1.1倍は115.5円です。切り捨てて115円になることを確かめています。

## テストを動かす

```bash
npx vitest run
```

```text
 ✓ price.test.ts (3 tests) 8ms

 Test Files  1 passed (1)
      Tests  3 passed (3)
```

3つのテストがすべて通りました（passed）。時間の数字は人によって違います。

## テストが失敗すると

`price.ts` の `Math.floor` を、四捨五入の `Math.round` に書き換えて保存し、もう一度動かします。

```bash
npx vitest run
```

```text
 ❯ price.test.ts (3 tests | 1 failed) 12ms
   ❯ withTax (3)
     ✓ 1000円の税込みは1100円 2ms
     × 1円未満は切り捨てる 7ms
     ✓ 0円は0円 0ms

 FAIL  price.test.ts > withTax > 1円未満は切り捨てる
AssertionError: expected 116 to be 115 // Object.is equality

- Expected
+ Received

- 115
+ 116

 ❯ price.test.ts:10:26
```

表示を上から読みます。

- `× 1円未満は切り捨てる`：このテストが失敗した
- `expected 116 to be 115`：115が返るはずなのに、実際には116が返った
- `Expected` が期待した値、`Received` が実際に返った値
- `price.test.ts:10:26`：失敗したのは、テストのファイルの10行目

「切り捨てる」という決まりを、うっかり四捨五入に変えてしまったことが、テストで見つかりました。人の目では1000円のような区切りのよい値だけを試して、見逃してしまいがちな間違いです。確かめたら、`Math.floor` に戻しておいてください。

:::tip[テストの説明は、決まりを書く]
`test` の説明には、「1円未満は切り捨てる」のように、守るべき決まりを書きます。失敗したときに、どの決まりが破られたのかがすぐに分かります。
:::

## 何をテストに書くか

すべての組み合わせを試すことはできません。次の3種類を意識して選びます。

- 普通の値：いちばんよく使われる場合（1000円）
- 境目の値：決まりが切り替わるところ（小数点以下が出る105円）
- 端の値：0や空など、忘れられやすい場合（0円）

## 困ったとき

- **「No test files found」と出た**：テストのファイルの名前が `.test.ts` で終わっているか確かめてください。
- **「Failed to resolve import "./price"」と出た**：`price.ts` がないか、名前が違います。
- **`npx vitest` だけを打ったら、終わらずに待ち続けている**：`run` を付けないと、ファイルの変更を見張り続ける動きになります。止めるときは `q` を打つか Ctrl+C を押してください。

## 確かめよう

1. `price.ts` に、割引の関数 `discount(price: number, rate: number): number` を足す。`rate` は割引の割合（0.2なら2割引き）で、1円未満は切り捨てる
2. `price.test.ts` に、`discount` のテストを3つ書く。普通の値、境目の値、端の値を1つずつ
3. `npx vitest run` で、すべて通ることを確かめる
4. わざと `discount` を間違えて、テストが失敗することを確かめてから元に戻す

`Tests  6 passed (6)` と出て、4でわざと間違えたときに失敗が見つかれば完了です。
