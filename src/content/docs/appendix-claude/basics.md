## このページでできるようになること

- Claude Code を入れて、プロジェクトのフォルダで動かせる
- セッション、トークン、コンテキストの考え方を説明できる
- `/clear` や `/compact` を使って、話の流れを整理できる

かかる時間の目安は45分です。

## 始める前に

第1部（コマンドライン）と第2部（Git と GitHub）を終えている必要があります。例では第10部の `~/practice/business-app` を使います。

:::note[付録について]
Claude Code を使うには、Claude の有料のプラン（Pro など）か、Claude Console のアカウントが必要です。本編を終えるために必須ではないので、付録にしています。
:::

## Claude Code とは

Claude Code はターミナルで動く AI の開発の道具です。普通のチャットと違い、プロジェクトのファイルを自分で読み、コマンドを打ち、ファイルを直すところまで行います。

できることが多い分、仕組みを知らずに使うと「途中から話が通じなくなった」「毎回同じ説明をしている」「思っていない所まで直された」ということが起きます。付録ではそうならないための考え方を学びます。

## 入れる

WSL2 の Ubuntu のターミナルで、公式の手順のコマンドを打ちます。入れ方は時期によって変わるので、公式の説明（code.claude.com/docs/ja/quickstart）でも確かめてください。

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

ターミナルを開き直してから、入ったことを確かめます。

```bash
claude --version
```

番号の後ろに `(Claude Code)` と出れば入っています。

## 動かす

プロジェクトのフォルダに移って、`claude` と打ちます。

```bash
cd ~/practice/business-app
claude
```

初めてのときは、ブラウザでログインするよう案内されます。ログインが終わると、入力欄が出ます。ここに、普通の言葉でお願いを書きます。

```text
このプロジェクトは何をするものか説明して
```

Claude Code はフォルダの中のファイルを自分で読んで答えます。ファイルの中身を貼り付ける必要はありません。

出るときは `/exit` と打ちます。`/` で始まるものは Claude Code への命令（コマンド）です。`/` だけを打つと、使えるコマンドの一覧が出ます。

## セッション、トークン、コンテキスト

Claude Code を上手に使うために、3つの言葉を押さえます。

| 言葉 | 意味 |
| --- | --- |
| セッション | `claude` を動かしてから止めるまでの、1回分の会話 |
| トークン | AI が文章を数える単位。日本語ではおおよそ1文字から数文字で1トークン |
| コンテキスト | AI がその時点で覚えていられる文章の全体。会話、読んだファイル、コマンドの結果がすべて入る |

コンテキストには上限があります。会話が長くなり、たくさんのファイルを読ませると、コンテキストがいっぱいに近づきます。Claude Code はいっぱいになると古いやり取りを要約して詰め直します（自動の圧縮）。このとき、前に伝えた細かい指示が要約から落ちることがあります。

「さっき言ったのに守ってくれない」と感じたら、コンテキストが圧縮された可能性を考えてください。

:::tip[セッションは毎回まっさらから]
新しいセッションは、前のセッションの会話を覚えていません。毎回伝えたいことは次のレッスンの CLAUDE.md に書いておきます。
:::

## 話の流れを整理する

| コマンド | すること | 使う場面 |
| --- | --- | --- |
| `/clear` | 会話を消して、まっさらから始める | 別の作業に移るとき |
| `/compact` | これまでの会話を要約して、コンテキストを空ける | 同じ作業を続けたいが、会話が長くなったとき。作業の区切りで自分から打つ |
| `/context` | コンテキストの使われ方を見る | 何がコンテキストを占めているか知りたいとき |

1つのセッションでいくつもの作業をすると、前の作業の話が次の作業の邪魔をします。作業が1つ終わったら `/clear` するのが基本です。

`/compact` は、自動の圧縮を待たずに作業の区切りで自分から打つのがおすすめです。自動の圧縮はいっぱいになった所で起きるので、作業の途中で大事な指示が要約から落ちることがあります。自分で打つときは、残してほしいことを後ろに書けます。

```text
/compact テストの方針と、まだ直していない所の一覧は残して
```

前のセッションに戻りたいときは、ターミナルで `claude -c`（直前のセッションを続ける）か `claude -r`（一覧から選んで戻る）と打ちます。

## 途中で止める

Claude Code が思っていない方向に進み始めたら、Esc キーを押すと止められます。止めたら、何が違うかを伝えてやり直させます。違う方向に進んだまま終わるのを待つより、早めに止めて伝え直すほうが、時間もコンテキストも無駄になりません。

## お願いのしかた

AI へのお願いは新しく入った同僚に頼むつもりで書きます。

- 何をしてほしいかを具体的に書く。「バグを直して」ではなく「社員の一覧で、部署のない人の行が表示されないので直して」
- 大きな作業は手順に分けて頼む
- いきなり直させず、まず読ませる。「まずコードを読んで、どこを直せばよいか説明して」

## 困ったとき

- **`claude: command not found` と出た**：ターミナルを開き直してください。それでも出るときは、公式の説明のインストールの困ったとき（Troubleshoot installation）を見てください。
- **途中から指示を守らなくなった**：コンテキストが圧縮された可能性があります。`/clear` して、必要なことを伝え直してください。

## 確かめよう

1. `~/practice/business-app` で `claude` を動かす
2. 「API のコントローラーはどこにあって、どんな URL を受け持っているか説明して」と頼む
3. `/context` でコンテキストの使われ方を見る
4. `/clear` してから、同じことを聞き直す

2で `api1/Controllers/` の下のファイルと、`/api/employees` や `/api/departments` の説明が返り、4で同じように答えられれば完了です。
