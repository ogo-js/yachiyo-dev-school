Claude Code は便利ですが、苦手なこともあります。ここでは、使っていてよく出会う「うまくいかない」を、症状ごとにまとめました。

付録の「安全に使う」では、AI が出す結果の間違い（テストを書き換える、ないものを書く、など）を扱いました。このページでは、作業の進み方がおかしくなったときの対処を扱います。

## 症状ごとの対処

| 症状 | 起きていること | 対処 |
| --- | --- | --- |
| 同じ直しを何度も繰り返す。直すたびに別の所が壊れる | 失敗した会話に引きずられて、同じ考え方から抜け出せなくなっている | Esc キーで止めて `/clear` する。何がだめだったかを自分でまとめて、頼み直す |
| 最初に伝えた指示を守らなくなった | 会話が長くなり、コンテキストの圧縮で指示が落ちた | 区切りで `/compact` し、残すことを指定する。毎回守ることは CLAUDE.md に書く |
| 何を言っても賛成する | AI は、頼んだ人の考えに合わせがち | 「問題点や反対の意見があれば先に言って」「根拠も示して」と頼む |
| 古い書き方で答える | AI が学んだ時点より新しいことは知らない | 公式の説明を読ませてから答えさせる（使いこなしのヒント） |
| やっていないのに「できました」と言う | 確かめずに報告することがある | 「テストを動かした結果を見せて」と頼む。最後は自分で動かして確かめる |
| 途中で止まる。質問ばかりする | 何をすれば終わりなのかが、はっきりしていない | 「テストが全部通るまで」のように、終わりの条件を書いて頼む |
| 返事が遅い。使える量の上限にすぐ届く | 大きなファイルや長い会話で、たくさんのトークンを使っている | `/context` で何が多いかを見る。読む作業はサブエージェントに任せ、作業ごとに `/clear` する。今の使った量は `/usage` で見られる |

## 2回うまくいかなかったら、やり方を変える

同じ頼み方で2回うまくいかなかったら、3回目も同じ頼み方をしても、たいていうまくいきません。次のどれかに切り替えます。

- plan のモードで、直す前に計画を出させる。計画の時点で考え違いを直す
- 作業を小さく分けて、1つずつ頼む
- 自分でコードを読んで、どこが問題かの見当を付けてから頼む

## AI に頼まないほうが早いこともある

1行の直しや、自分でどこをどう直せばよいか分かっている作業は、自分で書いたほうが早いことがよくあります。頼む文を書いて、結果を確かめる時間のほうが長くなるからです。

AI に任せるか自分でやるかを選べるのは、自分で書く力があるからです。本編で身につけたことは、AI を使うようになっても、そのまま役に立ちます。
