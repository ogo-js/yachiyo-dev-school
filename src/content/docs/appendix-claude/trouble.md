Claude Code は便利ですが、苦手なこともあります。ここでは、使っていてよく出会う「うまくいかない」を、症状ごとにまとめました。

付録の「安全に使う」では、AI が出す結果の間違い（テストを書き換える、ないものを書く、など）を扱いました。このページでは、作業の進み方がおかしくなったときの対処を扱います。最後に、使う量を抑える設定も載せています。

## 症状ごとの対処

| 症状 | 起きていること | 対処 |
| --- | --- | --- |
| 同じ直しを何度も繰り返す。直すたびに別の所が壊れる | 失敗した会話に引きずられて、同じ考え方から抜け出せなくなっている | Esc キーで止めて `/clear` する。何がだめだったかを自分でまとめて、頼み直す |
| 最初に伝えた指示を守らなくなった | 会話が長くなり、コンテキストの圧縮で指示が落ちた | 区切りで `/compact` し、残すことを指定する。毎回守ることは CLAUDE.md に書く |
| 何を言っても賛成する | AI は、頼んだ人の考えに合わせがち | 「問題点や反対の意見があれば先に言って」「根拠も示して」と頼む |
| 古い書き方で答える | AI が学んだ時点より新しいことは知らない | 公式の説明を読ませてから答えさせる（使いこなしのヒント） |
| やっていないのに「できました」と言う | 確かめずに報告することがある | 「テストを動かした結果を見せて」と頼む。最後は自分で動かして確かめる |
| 途中で止まる。質問ばかりする | 何をすれば終わりなのかが、はっきりしていない | 「テストが全部通るまで」のように、終わりの条件を書いて頼む |
| 返事が遅い。使える量の上限にすぐ届く | 大きなファイルや長い会話で、たくさんのトークンを使っている | `/context` で何が多いかを見る。読む作業はサブエージェントに任せ、作業ごとに `/clear` する。今の使った量は `/usage` で見られる。それでも上限に届くときは、下の「使う量を抑える設定」を見る |

## 2回うまくいかなかったら、やり方を変える

同じ頼み方で2回うまくいかなかったら、3回目も同じ頼み方をしても、たいていうまくいきません。次のどれかに切り替えます。

- plan のモードで、直す前に計画を出させる。計画の時点で考え違いを直す
- 作業を小さく分けて、1つずつ頼む
- 自分でコードを読んで、どこが問題かの見当を付けてから頼む

## 使う量を抑える設定

`/clear` やサブエージェントを使っていても、使える量の上限にすぐ届いてしまうときは、設定で会話が大きくなりすぎないようにします。ここで入れる設定は2つです。

| 設定 | すること |
| --- | --- |
| 自動の圧縮を早めに動かす | 会話が決めた大きさに達したら、自動で圧縮する |
| 探す役だけを軽いモデルにする | ファイルを探すサブエージェントを、安いモデルで動かす |

### なぜ会話が大きいと使う量が増えるのか

Claude Code は返事を作るたびに、そのセッションの会話全体をモデルに読み直させます。読み直した分も、使った量に数えられます。会話が5倍大きければ、返事1回あたりに使う量もおよそ5倍です。大きな会話のまま何十回もやり取りすると、短い質問を1つするだけでも多くの量を使います。

ですから、使う量を減らすのに一番効くのは、会話を大きいまま続けないことです。付録の「Claude Code と話す」で学んだ `/clear` と `/compact` はそのための道具です。ここでは、圧縮を自動で早めに動かす設定と、たくさん読む役を軽いモデルに任せる設定を足します。

### 自動の圧縮を早めに動かす

自動の圧縮は、何も設定しないとコンテキストの上限の近くで動きます。今のモデルの多くはコンテキストが100万トークンあり、約96.7万トークンに達するまで圧縮されません（この付録を書いた時点）。そこまでの会話は、ずっと大きいまま読み直され続けます。

Claude Code の入力欄で次のように打つと、会話が40万トークンに達した時点で自動の圧縮が動くようになります。

```text
/autocompact 400000
```

この値は、今使っているモデル用の設定として `~/.claude/settings.json` に保存され、次のセッションからも効きます。元に戻すときは `/autocompact auto` と打ちます。引数を付けずに `/autocompact` と打つと、今の上限を示す画面が開きます。

40万は一例です。小さくするほど使う量は減りますが、圧縮の回数が増えるぶん、伝えた指示が要約から落ちる機会も増えます。作業の区切りで自分から `/compact` して、残すことを指定する習慣は、この設定を入れても変わりません。

:::note[すべてのモデルにまとめて効かせたいとき]
`~/.claude/settings.json` に次の行を足すと、モデルによらず同じ値が効きます。`/autocompact` で保存した値があるモデルでは、そちらが優先されます。

```json
"autoCompactWindow": 400000
```

settings.json は JSON なので、カンマや引用符を1つ間違えると、次の起動のときに設定のエラーが出ます。そのときは直してから、起動し直してください。
:::

:::caution[自動の圧縮そのものが off になっていないか]
`/config` の Auto-compact が off だと、上限を決めても自動の圧縮は動きません。設定を入れても圧縮が起きないときは、まずここを確かめてください。`/config` はターミナルの Claude Code で開きます。
:::

### 探す役だけを軽いモデルにする

Claude Code は、ファイルを探す作業を Explore という最初から入っているサブエージェントに任せます（付録の「作業を分ける」）。Explore は何も設定しないと、メインの会話と同じか、それと同じくらい高いモデルで動きます。探して場所を返すだけの作業に、一番高いモデルを使っていることになります。メインの会話を Sonnet で動かしているなら、この設定は要りません。今のモデルは `/model` と打つと分かります。

`~/.claude/agents/explore.md` に次のファイルを置くと、最初から入っている Explore がこの定義に置き換わり、Sonnet で動きます。

```markdown
---
name: Explore
description: 読み取り専用の検索役。多くのファイルやフォルダを探し、見つけた場所と結論だけを返す
model: sonnet
tools: Read, Grep, Glob, Bash
---
指定された範囲を検索し、見つけた場所（ファイル:行）と結論だけを短く返す。
ファイルは変更しない。ファイル全文や長い検索結果は返さない。
```

- `name`：`Explore` にすると、最初から入っている Explore の代わりになる
- `model`：動かすモデル。`sonnet` のほか、もっと安い `haiku` も書ける
- `tools`：最初から入っている Explore と同じ、読むための道具。Bash は `git log` のように、コマンドで探すために渡している。ファイルを変えないことは、下の指示の文で頼んでいる
- 書き方は「作業を分ける」の「自分で作っておく」と同じ。`~/.claude/agents/` に置くと自分のすべてのプロジェクトで効き、Git には入らない

軽くするのは探す役だけにします。レビューや検証のように判断する役まで軽いモデルにすると、結果の質が下がります。

ファイルを置いたら、Claude Code を起動し直します。起動し直したら、次のように頼んで、Sonnet と返ってくれば置き換わっています。

```text
Explore のサブエージェントを1回動かして、そのサブエージェントが動いているモデルの名前を報告させて。
```

:::caution[frontmatter のキー名を間違えない]
`model` を `models` と書くなど、キー名を間違えると、その設定は効きません。エラーも出ないので、上の頼みで Sonnet と返ってこないときは、まずキー名を見直してください。
:::

### 効いているかを見る

| 打つもの | 分かること |
| --- | --- |
| `/context` | 今のコンテキストの使われ方。自動の圧縮が入ると、ここが小さくなる |
| `/usage` | プランで使える量を、今どれくらい使ったか |

効果はすぐには分かりません。何日か `/usage` を見て、同じような作業で減っているかを見てください。

### 元に戻す

| 戻したいもの | すること |
| --- | --- |
| 自動の圧縮の上限 | `/autocompact auto` と打つ。settings.json に行を足したときは、その行を消す |
| Explore の置き換え | `~/.claude/agents/explore.md` を消して、起動し直す |

## AI に頼まないほうが早いこともある

1行の直しや、自分でどこをどう直せばよいか分かっている作業は、自分で書いたほうが早いことがよくあります。頼む文を書いて、結果を確かめる時間のほうが長くなるからです。

AI に任せるか自分でやるかを選べるのは、自分で書く力があるからです。本編で身につけたことは、AI を使うようになっても、そのまま役に立ちます。
