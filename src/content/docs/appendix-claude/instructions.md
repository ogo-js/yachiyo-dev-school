## このページでできるようになること

- CLAUDE.md に、プロジェクトの決まりを書いておける
- 自分だけの決まりと、チームで共有する決まりを分けて置ける
- rule を使って、決まりを話題ごとのファイルに分けられる

かかる時間の目安は40分です。

## 始める前に

付録の「Claude Code と話す」を終えている必要があります。

## なぜこれを覚えるのか

前のレッスンで見たとおり、セッションは毎回まっさらから始まります。「テストは `npx vitest run` で動かす」「コミットの説明は日本語で書く」のような決まりを、毎回伝えるのは大変です。

CLAUDE.md は、Claude Code がセッションを始めるときに必ず読むファイルです。毎回伝えたいことはここに書いておきます。

## CLAUDE.md を作る

プロジェクトのフォルダのすぐ下に `CLAUDE.md` を置くと、そのプロジェクトで動かしたときに読まれます。

`/init` と打つと、Claude Code がプロジェクトを読んで、CLAUDE.md の下書きを作ってくれます。

```text
/init
```

できた下書きは必ず自分で読んで直します。AI が推測で書いた所や、書かなくてもコードを読めば分かる所が混ざっているからです。

## 何を書くか

書くのは、コードを読んでも分からないことと、毎回守ってほしいことです。

```markdown
# business-app

## 動かし方
- 画面：`cd rr1 && npm run dev`
- API：`cd api1 && dotnet run --urls http://localhost:5080`
- データベース：`docker compose up -d db`

## 確かめ方
- 画面を直したら `npm run typecheck` と `npx vitest run` を通す
- API を直したら `dotnet test api1.Tests` を通す

## 決まり
- SQL に値を入れるときは、必ずパラメーターを使う
- コミットの説明は日本語で書く
```

書き方のこつは次のとおりです。

- 短く書く。公式の説明では1つのファイルを200行未満にすることを目安にしています
- 具体的に書く。「きれいに書く」ではなく「インデントは空白2つ」
- 決まりどうしが食い違わないようにする。食い違うと、どちらが守られるか分からない

:::caution[CLAUDE.md は毎回コンテキストを使う]
CLAUDE.md は、毎回すべてがコンテキストに読み込まれます。長く書くほど、会話に使えるコンテキストが減ります。たまにしか使わない長い手順は、次のレッスンの skill に分けます。
:::

## 置き場所で、効く範囲が変わる

| 置き場所 | 効く範囲 | Git に入れるか |
| --- | --- | --- |
| `プロジェクト/CLAUDE.md` | そのプロジェクトで、チームの全員 | 入れる |
| `プロジェクト/CLAUDE.local.md` | そのプロジェクトで、自分だけ | 入れない（`.gitignore` に書く） |
| `~/.claude/CLAUDE.md` | 自分のすべてのプロジェクト | 個人の設定なので入れない |

チームで守る決まりはプロジェクトの `CLAUDE.md` に書き、Git で共有します。自分の好み（説明は短くしてほしい、など）は `~/.claude/CLAUDE.md` に書きます。

## rule で分ける

決まりが増えてきたら、`.claude/rules/` のフォルダに、話題ごとのファイルとして分けられます。

```text
business-app/
├── CLAUDE.md
└── .claude/
    └── rules/
        ├── sql.md       … SQL の決まり
        └── testing.md   … テストの決まり
```

`.claude/rules/` の Markdown のファイルは CLAUDE.md と同じように読み込まれます。ファイルの頭に `paths` を書くと、決まったファイルを扱うときだけ読み込まれるようにもできます。

```markdown
---
paths:
  - "api1/**/*.cs"
---

# SQL の決まり

- SQL に値を入れるときは、必ずパラメーターを使う
- `SELECT *` は使わず、列の名前を並べる
```

この rule は `api1` の C# のファイルを扱うときだけ読み込まれます。画面の作業をしているときは、コンテキストを使いません。

## 書いたら、確かめる

CLAUDE.md や rule を書いたら、新しいセッションで、守られるか確かめます。書き換えた内容は動いているセッションには途中から反映されないことがあるので、`/exit` してから `claude` を動かし直してください。

## 困ったとき

- **CLAUDE.md の決まりが守られない**：書き方があいまいか、ほかの決まりと食い違っていないか確かめてください。長いセッションでは、`/clear` して会話を短くすると守られやすくなります。
- **CLAUDE.md がどんどん長くなる**：コードを読めば分かることを書いていないか見直し、長い手順は skill に移してください。

## 確かめよう

1. `~/practice/business-app` に、上の例を参考に CLAUDE.md を作る
2. `.claude/rules/sql.md` に、上の SQL の決まりを書く
3. 新しいセッションで「社員を部署の番号で探す SQL を API に足して」と頼む

3で、パラメーター（`@id` など）を使った SQL を書き、`SELECT *` を使わなければ完了です。

## 今は知らなくてよいこと

- CLAUDE.md から別のファイルを読み込む書き方（`@` を使う）
- Claude Code が自分で覚え書きを残す仕組み（auto memory）
