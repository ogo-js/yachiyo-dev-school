## このページでできるようになること

- `/insights` で、自分の Claude Code の使い方のレポートを作れる
- レポートから、うまくいっていない所を読み取れる
- レポートの提案を、CLAUDE.md や skill の改善につなげられる

かかる時間の目安は30分です。

## 始める前に

付録の「安全に使う」を終えている必要があります。何週間か Claude Code を使って、セッションの記録がたまってから取り組むと、意味のあるレポートになります。

## なぜこれを覚えるのか

道具の使い方の癖は自分ではなかなか気づけません。同じ説明を何度もしていたり、何度も途中で止めて直させていたりしても、毎回のことなので当たり前になってしまいます。

`/insights` は、手元に残っているこれまでのセッションの記録を読んで、使い方をまとめたレポートを作るコマンドです。どんな作業に使っているか、どこでつまずいているか、CLAUDE.md に何を書くとよいかを示してくれます。

## レポートを作る

Claude Code の入力欄で、次のように打ちます。

```text
/insights
```

記録を読んでまとめるので、少し時間がかかります。終わると、レポートが HTML のファイルとして `~/.claude/usage-data/report.html` に保存されます。

Ubuntu の中のファイルなので、Windows のブラウザで開くには、Claude Code を動かしているのとは別のターミナルで次のように打ちます。

```bash
cd ~/.claude/usage-data
explorer.exe report.html
```

`explorer.exe` は Windows のエクスプローラーです。ファイルの名前を渡すと、そのファイルに合ったアプリで開きます。HTML のファイルなので、ブラウザで開きます。

## レポートの読み方

レポートには、おおよそ次のようなことがまとめられています。版によって、見出しや並びは変わります。

| 見る所 | 分かること |
| --- | --- |
| 使い方の概要 | どれくらい使っているか、どんな作業に多く使っているか |
| うまくいっていない所 | 頼んだことが伝わらなかった、動かないコードが出てきた、途中で止めた、などが多い所 |
| CLAUDE.md への提案 | よく繰り返している指示を、CLAUDE.md に書くための文 |
| 使っていない機能 | 使い方に合いそうなのに、まだ使っていない機能 |

まず「うまくいっていない所」を読みます。同じつまずきが何度も出ていれば、それが一番の改善の種です。

## 改善につなげる

レポートの提案はそのまま貼り付けず、自分で選んでから使います。付録で学んだ置き場所に当てはめて考えます。

| つまずき | 直し方 | 学んだレッスン |
| --- | --- | --- |
| 毎回同じ決まりを伝えている | CLAUDE.md に書く | 指示を置いておく |
| 特定のファイルのときだけの決まりがある | `paths` 付きの rule にする | 指示を置いておく |
| 毎回同じ手順を説明している | skill にする | 道具を足す |
| 調べものでコンテキストがすぐ埋まる | サブエージェントに任せる | 作業を分ける |
| 頼んでいない所まで直される | plan のモードで計画を確かめる | 安全に使う |

:::caution[提案も AI の出力]
レポートの提案も AI が書いたものです。CLAUDE.md に足す前に、本当に自分のつまずきに合っているか、ほかの決まりと食い違わないかを確かめてください。足しすぎると、CLAUDE.md が長くなってコンテキストを圧迫します。
:::

## 続けて振り返る

`/insights` は、一度で終わりにするものではありません。月に1回くらいの間隔で振り返り、直したことでつまずきが減ったかを見ると、使い方が少しずつ良くなっていきます。

ただし、レポートとセッションの記録は、既定では30日たつと Claude Code を起動したときに消されます。1か月後には、前のレポートが残っていないことが多いので、選んだつまずきや気づいたことは、メモに書き写しておきます。

## 困ったとき

- **レポートの中身が少ない**：セッションの記録がまだ少ないと、意味のあるまとめになりません。しばらく使ってから、もう一度試してください。
- **提案が自分の使い方に合わない**：提案はあくまで候補です。合わないものは使わなくてかまいません。

## 確かめよう

1. `/insights` でレポートを作り、ブラウザで開く
2. 「うまくいっていない所」から1つ選び、上の表のどの直し方が合うか決める。選んだつまずきはメモに書き写しておく
3. 決めた直し方を1つだけ試す（CLAUDE.md に1行足す、skill を1つ作る、など）
4. 1か月くらい使ってから `/insights` をもう一度動かし、メモと比べて、選んだつまずきが減ったか確かめる

2で直し方を1つ決め、3で実際に1つ直せれば完了です。4は時間をおいて続けてください。
