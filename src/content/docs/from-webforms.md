ASP.NET Web Forms（`.aspx`）で業務アプリを作ってきた人に向けたページです。

この教材に出てくる「API」や「セッション」のような言葉の多くは、名前が違うだけで、Web Forms で毎日使ってきたものに当たります。何に当たるかが分かると、本編のレッスンが読みやすくなります。

このページは対応を示すだけで、手を動かす所はありません。確かめるのは、表の右の列にある本編のレッスンで行ってください。Web Forms の経験があっても、本編は飛ばさずに順に進めてください。今まで意識せずに使ってきた仕組みの中身を、自分の目で確かめられます。

## API：`.asmx` も API だった

API は、プログラムが別のプログラムに仕事を頼むための窓口です。決まった形で頼むと、決まった形で結果が返ってきます。頼む側は、窓口の奥でどう処理しているかを知らなくてかまいません。

`.asmx` に `WebMethod` を書いて画面から呼んでいたなら、それはもう API です。名前を意識していなかっただけです。

違うのは、頼むときの包み方です。「名前に『佐』が入る社員の一覧をください」と頼む場合で比べます。どちらも説明のための例です。

`.asmx`（SOAP）では、次のように送ります。

```text
POST /EmployeeService.asmx
Content-Type: text/xml; charset=utf-8
SOAPAction: "http://tempuri.org/GetEmployees"

<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <GetEmployees xmlns="http://tempuri.org/">
      <name>佐</name>
    </GetEmployees>
  </soap:Body>
</soap:Envelope>
```

返ってくるのは、次のような XML です（外側の `soap:Envelope` は省いています）。

```xml
<GetEmployeesResult>
  <Employee>
    <Id>1</Id>
    <Name>佐藤</Name>
    <Department>総務部</Department>
  </Employee>
</GetEmployeesResult>
```

この教材の Web API（REST）では、同じお願いが1行で済みます。

```text
GET /api/employees?name=佐
```

返ってくるのは JSON です。

```json
[{"id":1,"name":"佐藤","department":"総務部"}]
```

| | `.asmx`（SOAP） | Web API（REST） |
| --- | --- | --- |
| 呼び方 | 「Web 参照の追加」などで作られたクラスのメソッドを呼ぶ。裏で HTTP の通信をしているが、コードには出てこない | URL とメソッド（GET・POST）を決めて、HTTP で送る。通信していることがコードに出てくる |
| メソッド | どのお願いも POST | 見るときは GET、変えるときは POST（レッスン3-2） |
| 渡す値 | XML の本文の中 | URL のクエリ文字列か、JSON の本文 |
| 返る形 | XML | JSON |

「社員の一覧を返す」という中身は同じで、包み方だけが違います。レッスン8-2で作るコントローラーのメソッド1つが、`WebMethod` 1つに当たります。

## 画面：`Page_Load` と `Click` のイベントの代わり

Web Forms では、1つの `.aspx` に、表示のときに動く `Page_Load` と、ボタンを押したときに動く `Click` のイベントを書きました。ボタンを押すと同じページに POST が送られ（ポストバック）、サーバーでイベントが動きます。

React Router でも、1つのページを3つの部品で作ります（レッスン7-4、7-5）。

| React Router | 動く場所 | Web Forms で近いもの |
| --- | --- | --- |
| `loader` | サーバー | `Page_Load`：表示する前にデータを取る |
| コンポーネント | サーバーとブラウザ | `.aspx` の画面：受け取ったデータで画面を描く |
| `action` | サーバー | ボタンの `Click` のイベント：送られた値で登録・更新する |

ただし、次の所が違います。

- **順番が逆です。** Web Forms のポストバックでは、`Page_Load` が動いてから `Click` のイベントが動くので、`IsPostBack` で分けていました。React Router では `action` が先に動き、終わると `loader` が自動でもう一度動いて、画面が新しくなります。`IsPostBack` のような分け方は要りません。
- **ボタンごとのイベントはありません。** 1つのページの `action` は1つです。1つのフォームに「保存」と「削除」のようにボタンが複数あるときは、ボタンに `name` と `value` を付けて、`action` の中で、どのボタンで送られたかを見て分けます。
- **ボタンを押してもサーバーに行かないことがあります。** Web Forms のボタンは、押すとポストバックしてサーバーで動きました。React のボタンの `onClick`（レッスン7-2）は、ブラウザの中だけで動きます。サーバーで登録や更新をしたいときは、`Form` で送って `action` で受けます。
- **登録した後は、別のページに移します。** POST の後の画面で F5 キーを押すと「フォームを再送信しますか」と聞かれ、同じ登録がもう一度行われるおそれがあります（レッスン3-2）。ポストバックの後に F5 キーを押したときに出る、あの確認です。`action` で登録したら、`redirect` で一覧などのページに移すと、これを防げます（レッスン7-5）。`Response.Redirect` と同じ役割です。

## セッション：`Session` に入れていたものの置き場所

サーバーが利用者ごとに値を覚えておく仕組みを「セッション」と呼びます。サーバーは「この番号の人の値はこれ」という表を持ち、ブラウザには番号（セッション ID）だけを Cookie で渡します。ブラウザが次のリクエストでその番号を送ってくるので、サーバーは表を引いて、誰の値かが分かります。

Web Forms の `Session` がこれです。初めの設定のままなら、表は IIS のメモリに置かれます。レッスン3-4の「サーバーが覚える作り」と同じです。

`Session` には何でも入れられて、どの画面からでも読めました。そのため、ログインした人、検索の条件、選んだ年度など、いろいろなものを入れていたと思います。

今の Web アプリでは、サーバーが利用者ごとの値を自分のメモリに持たない作りがよく使われます。サーバーを再起動すると表が消え、サーバーを2台に増やすともう1台は表を持っていないからです（レッスン3-4）。そのため、`Session` に入れていたものは、中身に合わせて置き場所を分けます。

| `Session` に入れていたもの | 今の置き場所 | 学ぶレッスン |
| --- | --- | --- |
| 誰がログインしているか | 署名を付けた Cookie（JWT など） | 3-4 |
| 一覧の検索の条件 | URL のクエリ文字列（`/employees?q=佐`） | 3-2、7-4 |
| 一覧で選んだもの（どの社員を詳しく見るか） | URL の一部（`/employees/3`） | 7-3 |
| 入力している途中の値 | 画面のフォーム。送るまではブラウザの中だけにある | 7-5 |
| 画面をまたいで覚えておきたいが、URL に載せられない作業中の値 | サーバーの外にある置き場所（データベースや Redis など） | この教材では扱わない |

URL に載せると、ブックマークや人に送った URL から同じ画面を開けるようになります。`Session` に入れていたときにはできなかったことです。ただし、パスワードのように人に見られてはいけない値は URL に載せません（レッスン3-2）。

:::note[サーバーの外にある置き場所]
アプリのサーバーとは別に動いていて、どのサーバーからも同じ値を読み書きできる置き場所です。アプリのサーバーを再起動しても消えず、台数を増やしても同じ値を読めます。何をどこに置くかはプロジェクトごとに決められていることが多いので、職場の決まりを確かめてください。
:::

:::note[別の意味の「セッション」]
付録の Claude Code で出てくる「セッション」は、Claude Code との一続きの会話のことです。ここでの意味とは関係ありません。
:::

## 画面の値：`ViewState` の代わり

Web Forms では、テキストボックスやドロップダウンの値を、ポストバックの間も `ViewState` が自動で保っていました。今の作りに `ViewState` はありません。値の種類ごとに、次のように扱います。

- 画面に表示するデータ：表示のたびに `loader` が取ってくる（レッスン7-4）
- 入力欄の値：フォームを送ると、`name` を付けた入力欄の値が送られる（レッスン3-2、7-5）
- ブラウザの中だけで変わる値（絞り込みの文字など）：`useState` で持つ（レッスン7-2）。ページを読み込み直すと消える

## 動かす場所：IIS からコンテナへ

Web Forms では、画面も Web サービスも、1つのアプリとして IIS に置いて動かすことが多かったと思います。この教材で作るアプリは、役割ごとに別のサーバーに分かれていて、それぞれをコンテナで動かします。

```text
Web Forms
  ブラウザ → IIS（.aspx と .asmx） → データベース

この教材
  ブラウザ → 画面のサーバー（React Router） → API のサーバー（ASP.NET Core） → データベース（PostgreSQL）
```

- 画面のサーバーの `loader` と `action` が、API を URL で呼びます（レッスン10-1）。
- 3つのコンテナは、`docker compose` でまとめて起動します（レッスン4-2、10-1）。
- ASP.NET Core は、.NET Framework と違って Windows でなくても動くので、Linux のコンテナの中で動かせます。
- `web.config` に書いていた接続文字列は、`appsettings.json` に書きます（レッスン8-3）。コンテナで動かすときは、環境変数で上書きします（レッスン10-1）。
